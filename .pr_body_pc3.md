## Bug Summary
The emotional state file is a single global path shared across ALL personalities. When switching personalities, the previous personality's emotional momentum carries over, causing cross-contamination.

## Severity: CRITICAL

## Actual Behavior
`_STATE_FILE` is defined as a single global `Path` object at module level. All personalities read from and write to the same file. When a user switches from "forge" (which built up frustration-driven emotional momentum) to "echo", echo inherits forge's emotional state instead of starting fresh or using its own baseline.

## Expected Behavior
Each personality should have its own isolated emotional state file, namespaced by personality ID. For example: `emotional_state_forge.json` and `emotional_state_echo.json`.

## Files Affected
- `src/personality_engine/emotional_state.py`
- `src/personality_engine/hooks.py`
- `tests/test_emotional_state.py`

## Before/After Proof
**Before:**
```python
_STATE_FILE = Path.home() / ".cache" / "personality-chips" / "emotional_state.json"

def _load_state() -> tuple[PADVector, float]:
    if not _STATE_FILE.exists():
        return PADVector(), 0.0

def _save_state(pad: PADVector) -> None:
    atomic_write_json(_STATE_FILE, ...)
```

**After:**
```python
_STATE_DIR = Path.home() / ".cache" / "personality-chips"

def _get_state_path(personality_id: str) -> Path:
    safe_id = personality_id.replace("/", "_").replace("\\", "_")
    return _STATE_DIR / f"emotional_state_{safe_id}.json"

def _load_state(personality_id: str) -> tuple[PADVector, float]:
    state_file = _get_state_path(personality_id)
    if not state_file.exists():
        return PADVector(), 0.0

def _save_state(personality_id: str, pad: PADVector) -> None:
    state_file = _get_state_path(personality_id)
    atomic_write_json(state_file, ...)
```
